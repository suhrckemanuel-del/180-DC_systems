## 1. What was attempted

Run the v2 reviewer prompt live and blind against the two eval cases that had no AI
review (02 framing drift, 04 internal contradiction), validate the outputs against the
contract, score them against the gold labels, change the prompt only where scoring
showed a pattern, and verify the source register before expert review. Live runs of
01, 03 and 05 and an independent fresh-context scorer were also attempted.

## 2. Cases run

Two live blind runs completed: 02 and 04. Each was generated by a fresh-context model
instance holding only the deployed prompt package (system prompt, rubric, contract,
case-01 calibration trio) and the filled team input template with the case file's
failure-mode header stripped. Gold labels stayed unread until the outputs existed.

Live runs of 01, 03 and 05, a fresh-context scorer and a fresh-context contrarian were
launched but killed by a session limit (resets 04:20). Scoring and the contrarian pass
were done inline by the orchestrator instead, which is disclosed in the scoring file.
Cases 01, 03 and 05 still carry their hand-worked reviews, so all five cases have a
review, but only 02 and 04 have live-generated ones.

## 3. Validation results

Both live outputs are valid JSON and pass the new contract validator
[check-review-v2.js](check-review-v2.js), including the verbatim-quote substring check
against the case text, the noise budget, readiness-versus-ceiling consistency, the
severity mapping, the ten-dimension order, the diagnosticMean arithmetic and the
em-dash lint. The three hand-worked reviews (01, 03, 05) also pass. Both live reviews
separate delivery-critical findings from learning notes, fill notAssessed, invent no
facts or sources, ghostwrite nothing and judge no person.

## 5. Failure clusters

One real cluster: noise in the late budget slots. Both reviews spent findings or
comments on topic-label titles and on polishing a recommendation their own top fix
says to replace. Case 04's title comment is an explicit false positive in the gold.
Restraint scored 2 of 3 on both cases; everything else required by the harness passed.
One consistency gap: identical blank input fields produced confidence Low on 02 and
Medium on 04. One friction point: both runners fought the character-for-character
quote rule against line-wrapped input.

## 6. Changes made

Only where the evidence showed a pattern, each with a decision-log entry:

1. Prompt synthesis protocol: findings mooted by a higher-ranked blocking fix fold in
   or drop, and communication findings go first when the budget forces a choice.
2. Prompt evidence rule and contract: a line wrap in pasted input counts as a single
   space inside a quote, and the validator comparison is whitespace-normalized.
3. Prompt missing-context rule: explicit confidence levels for partial input.
4. Source register corrections from a verification pass: Dell'Acqua citation and
   figures fixed to the working paper's numbers, Shi and Omachonu author spelling and
   venue caveat, S8 redated to January 2026 with a domain caveat, S9 figure confirmed,
   S10 rescoped to AI-assisted instructor feedback (also fixed in the expert one-pager).

The live runs predate the prompt changes, which is the correct order: the runs are the
evidence. Nothing was tuned to a single case; both edits generalize across the pair
and are tested by re-running the whole set.

## 8. Is expert review ready

Close but not yet. The two hardest blocking cases now have passing live blind runs and
the source register would survive a skeptical expert. But the expert pack's three
sample reviews (01, 03, 05) are hand-worked, not live outputs, and the prompt has
changed since the live runs. Ship the pack only after the full five-case set runs live
under the revised prompt and clears the harness threshold.

## 9. Is the validator ready

Yes. check-review-v2.js implements every check in the contract's section D and passes
all five current reviews. Remaining nice-to-have: a machine-readable gold format so
scoring itself can be scripted.

## 11. Risks and unresolved questions

- Tonight's scoring was done by the orchestrator, not an independent scorer. The
  numbers are strict but not fresh-context; step 3 above replaces them.
- The runner instances knew they were executing a prompt evaluation, which may make
  them more careful than a production Claude Project session. The Claude Project
  itself has not been exercised end to end.
- The mootness-pruning change could over-prune on evidence-rich decks or on case 05.
  The re-run in step 2 is the test.
- Cases are synthetic and short. Passing them bounds nothing about a real 30-slide
  deck with PDF extraction noise. The pilot remains the real test.
- Two runs is a small sample. Treat tonight as validation of the mechanism, not a
  measured pass rate.
