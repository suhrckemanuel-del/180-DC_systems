WHAT THIS IS. An AI tool that reviews a student consulting team's draft deliverables and
says how close to client-ready the work is, plus what to fix. It is a frozen system prompt
that emits one contract-valid JSON object, plus a self-contained HTML renderer that turns
that JSON into three views (student coaching, project lead, printable). It runs today with
zero infrastructure.

HOW TO TEST FUNCTIONALITY (normal LLM vs the code version).
- Testing the reviewer's judgment: a normal LLM is enough and is how every blind run was
  done. Paste the system prompt (04 section A) plus the rubric (01) plus the contract (03)
  plus the deck, get the JSON back. No code needed. That is the "is the review good" test.
- Trusting the JSON is well-formed: run node check-review-v2.js <review.json> <deck.md>. A
  normal LLM will happily emit subtly invalid JSON, the validator is what catches it.
- Seeing the actual product a student or lead uses: open index.html in a browser and paste
  the JSON. The student coaching gate and the ?role=student readiness gate only exist in the
  renderer, not in raw LLM output. Since student mode ships for everyone, the renderer is the
  product, not optional. It is still just a self-contained HTML file, no server.
- So the zero-infrastructure path for BOTH modes today is: Claude Project produces JSON, open
  the HTML and paste it. The serverless proxy only removes the copy-paste friction and
  enforces the sanitization gate. Build the proxy when the pilot needs it, not before.
